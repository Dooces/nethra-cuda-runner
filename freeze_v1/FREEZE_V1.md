# Nethra Freeze V1

This branch freezes the current minimal learning foundation after the purge and Fedora stress tests.

Frozen semantics:
- Every observed source/consequence coincidence may leave an ephemeral trace.
- Candidate competition is threshold-free. Positive predictive gain shares one local resource among currently active candidates.
- No relation is labelled correct, wrong, causal, body, object, hand, ball, useful, or useless by the learner.
- Persistent Nethra identity is non-hierarchical and append-only.
- Existing persistent Nethra are reinforced when later checkpoint evidence touches the same identity.
- Persistent strength decays lazily with elapsed experience; identity is not deleted.
- Weak persistent Nethra may remain dormant outside hot execution and can be locally looked up again.
- The hand/ball environment supplies only twelve independent motor currents and anonymous sensory activity.

Explicit software/runtime policy, not theory:
- cloud sample rate: candidate-processing budget.
- persistence floor: checkpoint compression only.
- execution epsilon: hot/cold scheduling only.
- CPU worker count.
- CUDA residency/execution policy.

Still experimental and not frozen as theory:
- decay half-life.
- conductance time constant.
- temporal direction/reactivation of a persistent relation as a higher-order source.
- any future action selection, value, reward, energy, attention, feeding, or button behavior.

The hand/ball continuation intentionally starts with hand-only development, writes and reloads a real Nethra memory checkpoint, then adds three physically simulated balls to the same sensory field and continues the same lineage. The learner is not told that a ball, hand, collision, or object exists.

The evaluator may inspect physical motor/afferent pairs, hand/ball pixel provenance, and collision counts after learning. These values never participate in competition or persistence.
